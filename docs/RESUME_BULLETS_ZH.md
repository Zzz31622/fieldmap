# FieldMap 简历写法

以下内容按项目真实实现编写。

## 项目一句话

独立设计并实现 FieldMap 客户数据接入工作台，将客户 CSV 转换为可审核的 CRM 字段映射、数据清洗预览、PII 检查和实施交接方案。

## 简历 Bullet

- 设计并实现 FieldMap 客户数据接入平台，覆盖 CSV 解析、字段类型推断、CRM Schema 映射、转换预览、数据质量评分、人工审核和 Markdown / JSON 交接导出。
- 基于规则引擎实现 9 个标准 CRM 字段映射，建立 8 组 Golden Case，当前 Top-1 字段映射准确率为 100%。
- 实现本地优先的数据安全边界：原始 CSV 仅在浏览器处理，可选 OpenAI 映射仅发送列名与推断类型，不发送样例值或客户行数据。
- 实现邮箱规范化、电话清洗、日期 ISO 转换、生命周期标准化，以及必填字段、重复目标、重复客户 ID、邮箱格式和 PII 检查。
- 使用 Node.js 原生测试覆盖 CSV Parser、字段推断、转换、审批阻断与 API 回退，当前 `10/10` tests 通过。

## 面试口述版本

“FieldMap 解决的是 FDE 交付里很常见的客户数据接入问题。客户发来的 CSV 字段名和产品 Schema 不一致，还可能有 PII、重复 ID、坏邮箱和日期格式问题。我的实现先做本地 CSV 解析和类型推断，再映射到标准 CRM 字段，并给人工提供覆盖入口。所有原始数据留在浏览器，可选模型只拿到列名和类型。最后系统输出质量分、问题队列和可导出的实施计划，而不是直接写 CRM。”

## 不要这样写

- 不写“已经接入 Salesforce 或 HubSpot 生产环境”。
- 不写真实客户数据转化率。
- 不写“自动完成数据入库”，项目明确保留人工审核。
